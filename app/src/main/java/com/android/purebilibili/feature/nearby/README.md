# 设备接力

客户端直接交换普通视频的 BV 号、分 P CID、进度、倍速、标题和封面，不传输视频文件、Cookie 或登录令牌。两端分别使用自己的登录状态和播放权限。

## 使用流程

1. 两端连接可互通的局域网，打开「设置 → 播放设置 → 跨设备播放 → 设备接力」，开启设备接力并保持面板打开。
2. 点击发现的设备，逐组核对两端显示的完整身份校验码，并在两端分别允许。
3. 从竖屏详情操作区或横屏播放器「更多 → 设备接力」选择已配对设备，上滑卡片或点击发送。
4. 接收端允许后显示准备视频、同步最新进度、等待播放确认的阶段提示，可取消接收。接收端准备视频页面和媒体；就绪时从发送端获取最新进度，恢复倍速并播放。收到实际播放确认后，发送端才暂停。准备期间发送端切换视频、进度、倍速或播放状态会中止交接。

设备身份持久保存。监听和连接只在接力开启且应用前台可见时保持；后台不会唤醒或自动播放。已连接设备标注「已连接」。关闭接收或解除配对会关闭相应连接。

## 手机与模拟器

模拟器可能收不到局域网发现广播。此时在手机生成五分钟有效的配对码，复制到模拟器的「无法发现？手动配对」，由模拟器发起连接，再在两端核对身份。配对码须完整复制，包括地址、公钥指纹和一次性令牌。

连接保持期间，两个方向都使用这条连接，不要求手机反向连接模拟器默认地址。断线或应用退到后台后，该连接会关闭；如果手机不能访问模拟器地址，在模拟器端点击已配对手机旁的「连接」，恢复双向连接即可。网络隔离本身无法由配对协议绕过。

## 协议与信任

- NSD 服务 `_bilipai._tcp.`，TCP 端口 39327；广播只提供候选地址，设备名称和广播指纹不直接建立信任。
- TLS 1.2/1.3 双向证书认证，私钥保存在 Android Keystore，不导出。首次配对仅在面板打开或配对码有效期内接纳候选身份；未建立信任前只允许身份确认。
- 两端展示由双方公钥指纹排序后计算的 128 位身份摘要，需逐组比对一致。双方确认后通过提交消息保存信任；后续操作必须匹配已信任证书公钥。
- 单条 TLS 流承载双向请求和回执，按请求编号关联；视频交接使用独立编号，最新进度只可获取一次并绑定接收设备。请求有超时、长度上限和并发上限；取消或超时关闭连接，终止未完成的准备。
- 消息协议版本为 2，两端需使用支持该版本的客户端。手动配对码仍用 `bilipai-pair://v1` 地址格式；地址格式版本与消息协议版本独立。
- 信任记录不参与云备份和设备迁移。解除配对删除本机记录并断开连接；不向对端远程删除其本地记录。
- 仅传递元数据，封面域名、播放参数和地址均受限。配对认证设备身份，不认证对端 APK 的发行身份。

## 动画与界面

保留 320 毫秒卡片飞出、飞入和失败回落，动态封面模糊及不超过 1.8dp 的边缘起伏。Android 12 及以上可用 GPU 模糊；低模糊预算和低版本降级，减弱动效关闭运动与模糊。玻璃开关显式隔离反光强度，MD3、Miuix 和玻璃共用应用组件与可滚动面板。未采集视频帧或页面背景。

## 回归场景

- 首次两端同意、任一端拒绝、身份校验码不一致、过期配对码、关闭面板和解除信任。
- 模拟器主动连接手机后，沿原连接分别向两个方向发送；断线后重新连接。
- 接收端延迟准备，确认取得最新进度；发送端切换分 P、拖动进度、暂停后不会被迟到回执暂停。
- 拒收、无播放权限、准备失败、请求超时、后台关闭；均不能让未完成的接力暂停发送端。接收端在交接失败时停止本次尚未确认的播放；已切换的内容或已接管的操作不再由交接清理控制。
- 设备离线或同名服务重新出现后，迟到的旧解析结果不能重新加入设备列表；连接断开应立即结束等待，并保留协议不兼容等具体原因。
- 手机、大屏、窄分屏、键盘展开；玻璃开关、MD3、Miuix 路径。

协议、身份校验码和双向请求回归用例位于相邻测试目录；执行状态在任务聊天中说明。
