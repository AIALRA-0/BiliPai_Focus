# 启动失败诊断

未开启增强诊断也会在应用私有目录 `files/logs/` 保留：

- `basic.log`：脱敏后的 Warning/Error 和固定启动阶段，滚动上限 64KB。
- `last_crash_log.txt`：最近一次本地崩溃快照，包含应用构建、系统版本、设备、异常及内存中的最近日志。
- `runtime.log`：增强诊断详细日志，滚动上限 256KB。关闭增强诊断只清除此文件及详细内存记录，不清除基础日志或崩溃快照。

日志不进入系统备份。普通文件管理器不能直接读取内部私有目录，用户需要主动导出。导出文件合并基础、增强和最近一次崩溃快照；即使普通日志为空，或用户之前关闭过闪退提示，保留的快照仍可导出。读取和文件复制在后台排队，避免阻塞诊断页面。

## 连续启动失败

同一构建在 5 分钟内连续两次启动未完成，第三次启动进入恢复模式。恢复状态会保留到用户主动重试，或安装不同构建。用户正常离开主界面，或主界面连续在前台运行 15 秒，会清除失败计数；配置变化不会作为正常退出处理。

恢复模式跳过应用主题偏好、网络、首页、播放器和插件等常规初始化。主入口直接打开私有的 `StartupRecoveryActivity`。页面使用系统原生控件，避免依赖 Compose、模糊效果或播放器，支持系统深浅主题、可滚动内容、平板最大内容宽度和不小于 48dp 的按钮。

- **导出并分享诊断日志**：读取已保留的本地日志，不运行 Android 17 profiling API。Android 10+ 尝试保存到公共 `Download/BiliPai/logs/`；不能写公共下载目录时仍可通过系统分享读取缓存文件。
- **重试正常启动**：恢复常规初始化，不清理账号、设置或崩溃快照。如果再次启动失败，下次打开会回到诊断页。
- **暂时退出**：保留日志及恢复状态。

这不是启动崩溃本身的修复。Application 创建之前、ContentProvider 初始化或主 Activity 类加载阶段的故障仍可能阻止恢复入口出现，需要系统错误报告或 ADB 日志。系统杀进程也可能留下未完成启动标记，因此页面不将其直接断言为 Java 崩溃。混淆堆栈仍需要对应安装包的 `mapping.txt` 还原。

## 验证清单（须另行授权编译或设备验证）

1. 关闭增强诊断，记录 Warning/Error，重启后导出，确认基础记录保留。
2. 仅保留崩溃快照、清空普通日志，确认普通导出仍带堆栈；关闭闪退提示后重复验证。
3. 在隔离测试安装中模拟两次启动阶段故障，第三次打开应进入原生恢复页；导出应无需首页。
4. 从恢复页退出、重新打开、切换主题或旋转设备，确认仍可导出。验证 Android 8/9 无存储权限时可通过分享发送日志。
5. 主动重试后再次失败应回到恢复页；重试成功并保持前台 15 秒后不应再进入恢复模式。
6. 正常退到后台、配置变化以及升级构建不应误积累为连续启动失败。
